## Session — 2026-09-21

**Did:**
- **Closed the Phase 0 waveform gate.** Diagnosed `0002-adder-unknown` from `broken.vcd` with the
  mechanism withheld, and named it before decoding the spoiler: `cout` was driven from
  `carry[WIDTH-1]`, the carry *entering* the MSB, instead of `carry[WIDTH]`, the carry leaving it.
  The whole chain and every sum bit were correct; the fault was one wire at the module boundary.
  The pinning evidence is one line: at 15 ns `u_add.g_bit[3].u_fa.cout` reads 0 while the module's
  `cout` reads 1 — a module output contradicting the only signal that feeds its position.
- Verified the diagnosis instead of trusting it. A hand-simulated `cout = carry[3]` reproduces all
  128 observed failures exactly, none missed, no false positives.
- Fixed the spoiler decode command in `0002/NOTES.md`, which never ran on this machine: BSD
  `base64` requires `-i` for a file argument.
- **Built the ALU** (`rtl/04_alu.sv`): add, sub, and, or, xor, sll, srl, sra, slt, sltu. One
  `ripple_adder` from `02_adder.sv` serves all four arithmetic paths — sub is `a + ~b + 1`, and
  both comparisons are that subtraction with the difference discarded and a flag kept. `sltu` is
  the borrow (`~cout`); `slt` is `sign(diff) ^ overflow`.
- Encoded the ops as RV32I's `{funct7[5], funct3}` rather than inventing a numbering. ADD/SUB and
  SRL/SRA then differ in exactly one bit, as the ISA intends, which makes the Phase 2 decoder a
  wire instead of a lookup table. A free decision now that costs nothing and saves work twice.
- **Passed the Phase 1 ALU gate**: 207,232 cases against a golden model — 3,136 directed (every
  pair from a 14-value edge set × all 16 encodings), 4,096 exhaustive at `WIDTH=4`, 200,000
  randomised on a fixed seed so any failure reproduces. Signed/unsigned and shift masking are hit
  by construction, not by luck: the edge set contains 0, 1, −1, INT_MIN, INT_MAX and shift amounts
  31 / 32 / 33 / −32.
- Wrote `scripts/mutate-alu.sh` + `make mutate-alu`: injects seven classic ALU bugs one at a time
  and checks the bench reddens for each. All seven killed.
- **The mutation test paid for itself immediately, with a number I did not expect.** Six mutations
  died loudly — 6,000 to 36,000 failures each. One died by a thread: dropping SUB's carry-in
  (`a + ~b`, no `+1`) was caught by exactly **30** SLT/SLTU cases out of ~25,800. The reason is
  arithmetic, not luck: `a + ~b` is `a - b - 1`, so `~carry_out` yields `a <= b` where the answer
  wanted is `a < b`. **The two differ only when `a == b`.** And 30 is not approximately anything —
  it is 14 diagonal pairs from the directed edge set plus 16 from the 4-bit exhaustive sweep,
  exactly. The 200,000 randomised cases contributed **zero**, because `P(a == b) = 2⁻³²`.
  So: a random sweep two thousand times larger than the directed one found none of it. Directed
  edge sets are not a warm-up for randomisation and randomisation does not subsume them — equality,
  boundaries and identities have measure zero in a random space and must be placed by hand. Had I
  written the bench as "200k random cases, that's surely thorough", this bug would have shipped
  into the register file and then into the core.

**Broke / didn't work:**
- **`0003` — the first real bug of the project, and it was in the reference, not the design.**
  First `make alu` run: 6,080 failures, all of them SRA, none anywhere else. The model computed
  `(sa >>> sh) & mask`. `>>>` is arithmetic only while its left operand is signed, and
  SystemVerilog resolves signedness across the whole expression *before* evaluating it — `mask` is
  unsigned, so `sa` was converted to unsigned and `>>>` silently became `>>`. Nothing warns and
  the operator is still spelled `>>>`.
- I arbitrated before editing: −32 arithmetic-shifted right by 1 is −16 = `0xFFFFFFF0`, which is
  what the ALU produced; `0x7FFFFFF0` is the logical shift. **The ALU was right and my golden model
  was wrong.** Fixing the DUT to satisfy the broken reference would have corrupted correct hardware
  and then passed. That is the near-miss worth remembering, not the signedness rule.
- A comment in my own RTL stated the wrong reason for its own code. I wrote that `use_sub` cannot
  be `op[3]` because SRA has bit 3 set and must not invert `b`. Mutation testing refuted it: wiring
  `use_sub` to `op[3]` fails 9,728 cases and **every one is SLT or SLTU, not one is SRA** — because
  SRA's result never comes from the adder, so inverting `b` there is merely wasted power. The real
  constraint is the opposite direction: SLT and SLTU have bit 3 *clear* and both must subtract.
  Comment corrected to say what the mutation proved.

**Confused about:**
- Nothing blocking on the ALU. The open question is ordering (below), not design.

**Found without writing any code:**
- **The `sed`-delimiter tax.** Two mutation attempts failed to apply because SystemVerilog
  expressions are dense with `|`, `/` and `(`, which collide with every `sed` delimiter. A
  silently-unapplied mutation looks exactly like a *surviving* mutation — the bench appears blind
  when in fact nothing was ever changed. `scripts/mutate-alu.sh` therefore patches with Python and
  **exits non-zero if the target string is absent**, so "source moved" can never be misread as
  "bench is blind". A negative result needs its own integrity check.
- **A hypothesis list must span levels of hierarchy, not just vary within one.** Three candidates
  that are all corruptions of one Boolean expression inside one cell are not three hypotheses. Spread
  them across cell logic → interconnect → module boundary → integration *before* spreading them
  within any one level. `0002` was at the module boundary; a list confined to cell logic could not
  have contained the answer at any length.

**What the source actually says:**
- **GT06 is 16 protocols sharing an envelope.** `Gt06ProtocolDecoder.java:130` declares a 16-member
  `Variant` enum, tested at **35** branch sites, alongside **71** message-type constants tested at
  **110** sites, in 1,705 lines. `STANDARD` is one enum member, not a norm the others deviate from.
- **JT808 picks its framing, its escape alphabet and its header layout at runtime.** Three frame
  starts (`(`, `0x7e`, `0xe7`), found by a byte-at-a-time three-way scan; two different escape
  alphabets selected by the delimiter — the alternative mode has two introducer bytes and four
  pairs against the standard's one and two.
- **Header length is a function of three fields read from three different places:** `attribute`
  bit 14 (+1 byte, ID 6→10), the delimiter byte (ID 6→7 when `0xe7`), and the message *type*
  (index 2→1 for two types). You must read and branch on all three before you know where the body
  begins.

## Session — 2026-09-21 (fourth): deciding 0007

**Did:**
- Merged PR #4. **Decided `0007`:** the stateless decoder is *the* reference result; the cached
  decoder is a declared second mode reported beside it; the difference between them is the
  dispatch-cost measurement.
- Updated `bench/README.md` with the manifest parameters that follow: `detection_mode` on every
  result, plus connection count and frames-per-connection for cached runs only.

**The argument that actually decided it** — and it was not the one I expected going in. I had this
filed as a performance-realism question: stateless is the honest worst case, cached is closer to
deployment, pick your trade-off. It is not that. Reading the recorded predictions side by side:

```
A  "frame synchronisation and PER-MODEL DISPATCH dominate"
B  "frame sync and dispatch are O(1) PER FRAME; the checksum is O(n)"
```

A cached decoder makes dispatch O(1) per *connection* rather than per frame. **That is
Prediction B's position, implemented.** Building the reference that way would bake one side of the
dispute into the artifact whose only job is to settle it. Stateless does not assume A is right —
it declines to optimise. One option pre-judges the question and the other does not, and that
asymmetry decides it on its own. The realism trade-off never had to be adjudicated at all.

**Broke / didn't work:**
- **I put a wrong number in my own options list, and it argued against the option that won.**
  Option 3 was written as "roughly doubles reference-decoder work." It does not: detection sits
  behind one interface and the decoder body is shared, so the second mode is a session map plus a
  revalidate-on-failure path — call it 15%. Corrected in place with a note rather than quietly
  dropped, because the whole point of keeping rejected options is to show what the choice was
  weighed against, and a cost estimate that was wrong by 6× is exactly the kind of thing that
  silently steers a decision. Worth noticing that the estimate was invented at the moment of
  writing and never checked against anything.

**Found without writing any code:**
- **Prediction A is two costs, not one, and the project only had an instrument for one of them.**
  A bundles *resync* (finding frame starts after garbage) with *dispatch* (choosing which variant
  decoder runs). Resync rate is already a declared stimulus parameter and the roadmap calls it
  "the discriminator." Dispatch had nothing. The stateless↔cached delta is that missing
  instrument, so running both modes decomposes A into two independently measurable halves rather
  than one lump — strictly more than Phase 4 could otherwise conclude.
- That reframes why the second mode gets built in Phase 0 instead of deferred: not for realism,
  but because it is a *measuring instrument*, and `0004`'s argument about artifacts built after
  profiling applies to instruments as much as to benchmarks.

## Session — 2026-09-21 (fifth): three of my own justifications did not survive

**Did:**
- Merged PR #5. Then had `0007` reviewed, and **amended it rather than defending it.** The
  decision stands — both modes built, delta as instrument — but three claims I used to justify it
  were wrong.
- Recorded **Prediction C** in the roadmap, dated, before any data exists.

**What was wrong, in order of how much it mattered:**

- **"Stateless declines to optimise" was the wrong frame.** Stateless is not the absence of a
  choice — it sets per-frame dispatch to its *maximum*, exactly as cached sets it near its
  minimum. They bracket the term from opposite ends and neither is neutral. The core argument
  survives (a cached reference would implement B's position inside the artifact meant to settle A
  vs B; stateless does not presuppose A), but calling the stateless figure "the reference result"
  unqualified invites Phase 4 to read a *bound* as a *finding*, in the direction favouring A.
  Resolved by separating the two uses: stateless is the denominator for platform speedup claims,
  which is all `0004` ever meant; the stateless–cached **range** is what characterises the
  workload. Neither endpoint is quoted alone as a description.
- **"O(1) per connection" is false at line rate**, which is the rate `0001` commits to. It assumes
  frames from one device arrive together. They interleave, so every frame needs a state lookup.
  Caching does not remove a per-frame cost — it trades a branch-heavy one for a memory-heavy one.
- **The delta does not measure "dispatch cost."** It measures *detection minus lookup*, and which
  dominates is set by connection count: few connections and the delta approximates detection; many
  interleaved with a miss per frame and it shrinks to nothing or inverts. Connection count was
  written down as a parameter of the cached run. It is not — it decides what the second instrument
  measures at all, so it is promoted to a discriminator alongside resync rate.
- **The 15% estimate had the same provenance as the "roughly double" it replaced.** Invented while
  writing, never checked, against code that does not exist — and carrying the locality assumption
  the point above demolishes. I had written up replacing it as if it were a correction. It was
  not; it was a better-reasoned guess wearing a correction's authority. Marked in `0007` as an
  unchecked estimate to be measured. **Replacing a bad estimate with a better-reasoned one is not
  the same as checking it**, and I did not notice the difference while congratulating myself on
  the first catch.

**Broke / didn't work:**
- Nothing in the tree. The failures this session were all in reasoning I had already committed.

**Found without writing any code:**
- **Device identity is carried by the connection, not the frame — verified, and unconditional for
  GT06.** `Gt06ProtocolDecoder.java:526` resolves by IMEI *only* inside `if (type == MSG_LOGIN)`;
  line 502 handles every other type with `getDeviceSession(channel, remoteAddress)` and no id.
