**Found without writing any code:**
- GT06 frames start `7878` or `7979`. JT/T 808 frames start **and end** with `7e`. So the two are
  framed differently in kind — length-prefixed versus delimiter-terminated — and that is the
  *root* of the escaping asymmetry in Prediction B rather than a detail of it. One line of a
  protocol-identification table.

  frame-boundary error, in production, in a mature codebase). The generator must emit malformed
  frames deliberately at a realistic rate; `bench/README.md` now says so.

## Session — 2026-09-21

**Did:**
- **Closed the Phase 0 waveform gate.** Diagnosed `0002-adder-unknown` from `broken.vcd` with the
  mechanism withheld, and named it before decoding the spoiler: `cout` was driven from
  `carry[WIDTH-1]`, the carry *entering* the MSB, instead of `carry[WIDTH]`, the carry leaving it.
  The whole chain and every sum bit were correct; the fault was one wire at the module boundary.
  The pinning evidence is one line: at 15 ns `u_add.g_bit[3].u_fa.cout` reads 0 while the module's
  `cout` reads 1 — a module output contradicting the only signal that feeds its position.
- Verified the diagnosis instead of trusting it. A hand-simulated `cout = carry[3]` reproduces all
  128 observed failures exactly, none missed, no false positives.
- Fixed the spoiler decode command in `0002/NOTES.md`, which never ran on this machine: BSD
  `base64` requires `-i` for a file argument.
- **Built the ALU** (`rtl/04_alu.sv`): add, sub, and, or, xor, sll, srl, sra, slt, sltu. One
  `ripple_adder` from `02_adder.sv` serves all four arithmetic paths — sub is `a + ~b + 1`, and
  both comparisons are that subtraction with the difference discarded and a flag kept. `sltu` is
  the borrow (`~cout`); `slt` is `sign(diff) ^ overflow`.
- Encoded the ops as RV32I's `{funct7[5], funct3}` rather than inventing a numbering. ADD/SUB and
  SRL/SRA then differ in exactly one bit, as the ISA intends, which makes the Phase 2 decoder a
  wire instead of a lookup table. A free decision now that costs nothing and saves work twice.
- **Passed the Phase 1 ALU gate**: 207,232 cases against a golden model — 3,136 directed (every
  pair from a 14-value edge set × all 16 encodings), 4,096 exhaustive at `WIDTH=4`, 200,000
  randomised on a fixed seed so any failure reproduces. Signed/unsigned and shift masking are hit
  by construction, not by luck: the edge set contains 0, 1, −1, INT_MIN, INT_MAX and shift amounts
  31 / 32 / 33 / −32.
- Wrote `scripts/mutate-alu.sh` + `make mutate-alu`: injects seven classic ALU bugs one at a time
  and checks the bench reddens for each. All seven killed.
- **The mutation test paid for itself immediately, with a number I did not expect.** Six mutations
  died loudly — 6,000 to 36,000 failures each. One died by a thread: dropping SUB's carry-in
  (`a + ~b`, no `+1`) was caught by exactly **30** SLT/SLTU cases out of ~25,800. The reason is
  arithmetic, not luck: `a + ~b` is `a - b - 1`, so `~carry_out` yields `a <= b` where the answer
  wanted is `a < b`. **The two differ only when `a == b`.** And 30 is not approximately anything —
  it is 14 diagonal pairs from the directed edge set plus 16 from the 4-bit exhaustive sweep,
  exactly. The 200,000 randomised cases contributed **zero**, because `P(a == b) = 2⁻³²`.
  So: a random sweep two thousand times larger than the directed one found none of it. Directed
  edge sets are not a warm-up for randomisation and randomisation does not subsume them — equality,
  boundaries and identities have measure zero in a random space and must be placed by hand. Had I
  written the bench as "200k random cases, that's surely thorough", this bug would have shipped
  into the register file and then into the core.

**Broke / didn't work:**
- **`0003` — the first real bug of the project, and it was in the reference, not the design.**
  First `make alu` run: 6,080 failures, all of them SRA, none anywhere else. The model computed
  `(sa >>> sh) & mask`. `>>>` is arithmetic only while its left operand is signed, and
  SystemVerilog resolves signedness across the whole expression *before* evaluating it — `mask` is
  unsigned, so `sa` was converted to unsigned and `>>>` silently became `>>`. Nothing warns and
  the operator is still spelled `>>>`.
- I arbitrated before editing: −32 arithmetic-shifted right by 1 is −16 = `0xFFFFFFF0`, which is
  what the ALU produced; `0x7FFFFFF0` is the logical shift. **The ALU was right and my golden model
  was wrong.** Fixing the DUT to satisfy the broken reference would have corrupted correct hardware
  and then passed. That is the near-miss worth remembering, not the signedness rule.
- A comment in my own RTL stated the wrong reason for its own code. I wrote that `use_sub` cannot
  be `op[3]` because SRA has bit 3 set and must not invert `b`. Mutation testing refuted it: wiring
  `use_sub` to `op[3]` fails 9,728 cases and **every one is SLT or SLTU, not one is SRA** — because
  SRA's result never comes from the adder, so inverting `b` there is merely wasted power. The real
  constraint is the opposite direction: SLT and SLTU have bit 3 *clear* and both must subtract.
  Comment corrected to say what the mutation proved.

**Confused about:**
- Nothing blocking on the ALU. The open question is ordering (below), not design.

**Found without writing any code:**
- **The `sed`-delimiter tax.** Two mutation attempts failed to apply because SystemVerilog
  expressions are dense with `|`, `/` and `(`, which collide with every `sed` delimiter. A
  silently-unapplied mutation looks exactly like a *surviving* mutation — the bench appears blind
  when in fact nothing was ever changed. `scripts/mutate-alu.sh` therefore patches with Python and
  **exits non-zero if the target string is absent**, so "source moved" can never be misread as
  "bench is blind". A negative result needs its own integrity check.
- **A hypothesis list must span levels of hierarchy, not just vary within one.** Three candidates
  that are all corruptions of one Boolean expression inside one cell are not three hypotheses. Spread
  them across cell logic → interconnect → module boundary → integration *before* spreading them
  within any one level. `0002` was at the module boundary; a list confined to cell logic could not
  have contained the answer at any length.

**Broke / didn't work:**
- **The harness silently ate the last character of its own output.** `htif_exit` wrote the exit
  command without waiting for Spike to consume the pending `putchar`, so the trailing newline
  vanished — no error, no warning, just a missing byte. Caught only because `cat -e` was used to
  look at line endings rather than trusting that the output looked fine. A result whose final byte
  depends on a race is not a result. `htif_exit` now drains `tohost` first.
- **`scripts/capture.sh` recorded the wrong compiler.** It probed `riscv32-unknown-elf-gcc`, which
  does not exist on this machine; the actual compiler is `riscv64-elf-gcc`. Every manifest would
  have logged "not installed" for *the single most important provenance field in a Spike reference
  capture*, and it would have looked like a filled-in table. Fixed, and binutils added alongside.
  This was written weeks before there was any toolchain to check it against — an untested provenance
  field is not provenance.
- **zsh word-splitting cost me two broken probes.** `for spec in "rv32im ilp32"; set -- $spec` and
  `$CC $FLAGS ...` both pass the whole string as ONE argument, because zsh does not word-split
  unquoted expansions the way bash does. The first produced a bogus "gcc cannot target rv32"
  conclusion that was wrong; `--print-multi-lib` contradicted it within the same command, which is
  the only reason it was caught. The fix that matters is not "quote better" — it is that flag lists
  belong in a Makefile, where `sh` runs them and they are recorded, not in shell variables.
