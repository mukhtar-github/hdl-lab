**Broke / didn't work:**
- **GTKWave installs but does not run on this Mac.** Launches and dies, printing nothing.
  This blocks the Phase 0 gate, which is specifically *"find a deliberately introduced bug by
  reading a waveform, without print statements"* — a gate that cannot be passed without a
  working viewer. *(Resolved same session: exit status is 137 = SIGKILL, not a crash. The
  Homebrew cask ships an x86_64-only binary dated October 2020; this is an arm64 Mac with no
  Rosetta, so the kernel kills it on exec. It has never run once. Replaced with Surfer 0.7.0,
  native arm64, which parses all three Project 1 VCDs — verified headlessly with `surfer server
  --file`. Written up as `decisions/0005`.)*
- **`make lint` was checking nothing and reporting success.** `-Wall` makes Verilator's
  cosmetic DECLFILENAME warning fatal, so both invocations aborted before analysing any logic,
  and a trailing `|| true` swallowed the non-zero exit. It had never once linted this code.
  Worse: the two hardcoded top modules (`counter`, `ripple_adder`) excluded `shift_blocking` —
  so the one module in the repo that is *wrong on purpose* was the one the linter could never
  see. Verilator flags it loudly (`BLKSEQ`) the moment you point it there. Fixed: `make lint`
  now covers 8 modules and fails on any warning; `make lint-trap` demonstrates the catch.
- README claimed the two shift registers diverge by three cycles. Measured from the testbench
  print: blocking asserts at cycle +0, non-blocking at cycle +2 — two cycles apart. The
  absolute latencies in the RTL comments (3 edges vs 1) were right; the relative claim was not.

**Confused about:**
